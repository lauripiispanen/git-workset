Keep git.Drop the full checkout.

Named sparse-checkout profiles for git worktrees. The partial-checkout workflow Perforce teams have taken for granted for years — without switching platforms.

Built for repos that got big

Not everyone on the team needs every file. git-workset lets you define exactly who gets what — and enforces it with a single committed config.

Game studios

Source + assets in one repo

Your rendering team shouldn’t clone 80 GB of source audio every morning. Define a renderer profile that skips LFS audio and motion-capture data. A 45-minute checkout becomes 5 minutes.

Platform & infra

Monorepo without the slog

Fifty services in one repo means fifty thousand files irrelevant to today’s task. Carve a worktree scoped to your service, with shallow submodules and nothing else on disk.

Teams on the fence

No Perforce migration required

Perforce’s main draw for large teams is workspace-level file filters. git-workset brings that exact model to git. Your CI, IDE, hooks, and existing workflows stay completely unchanged.

One config file, one command

Commit .git-workset.toml to the repo root. Everyone gets the same profiles — no scripts to share, no per-machine setup.

.git-workset.toml 
[workset.server]
description = "Backend server work"
include     = ["src/server", "src/shared"]
exclude_lfs = ["*.psd", "*.fbx", "*.wav"]
sparse_cone = true

[workset.server.submodules]
shallow = true
skip    = ["third_party/art-pipeline"]

[workset.art]
description  = "Full asset pipeline"
include      = ["src/client", "assets"]
include_lfs  = ["*.psd", "*.fbx"]
usage 
# Clone — server files only
git workset clone git@github.com:org/repo.git \
  ./repo --workset server

# New branch + scoped worktree
git workset carve ../feature \
  -b my-feature --workset server

# Compose profiles when you need both
git workset carve ../fix \
  -b fix main --workset server+art

Why it matters

01

Checkout time drops from hours to minutes

Sparse cone combined with per-profile LFS filters means clones pull only what each workset actually needs. No waiting on gigabytes of assets unrelated to the task at hand.

02

Profiles live in the repo, not in people’s heads

The .git-workset.toml is committed alongside the code. New engineers get the right workset on day one — no onboarding wiki page that’s three years out of date, no “ask someone” step.

03

It’s git all the way down

git-workset creates ordinary worktrees with sparse checkout and LFS filters applied. Your CI, IDE, git hooks, and scripts are unchanged. Nothing needs to learn about worksets except the engineers who want them.

Install

// Homebrew — macOS & Linux

brew install lauripiispanen/tap/git-workset

// Pre-built binary

Download for macOS, Linux, or Windows from GitHub Releases. Extract and place on your PATH.

// From source

cargo install --git https://github.com/lauripiispanen/git-workset

git auto-discovers git-workset as a subcommand — use git workset directly once installed.
